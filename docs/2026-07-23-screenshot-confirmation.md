# 截图确认与后台捕获规格

## 目标

用户浏览网页或使用其他应用时，通过 `Control + 1` 直接进入截图，不切换到 IdeaCard 主窗口。用户完成区域选择后，可以在截图下方补充一段可选的「我的想法」，再明确决定取消或保存普通截图；保存后截图和想法一次进入同一张卡片。滚动截图入口因稳定性不足暂时屏蔽。

## 交互流程

1. 用户按下 `Control + 1`。
2. IdeaCard 保持后台，在所有显示器上显示原生截图遮罩；鼠标变为十字光标。遮罩必须接收窗口激活过程中的第一次鼠标事件，不得让首次按下只用于激活窗口。
3. 用户第一次按下并拖拽即可选择区域。选区外变暗，选区保留原画面；选区显示边框和八个调整点，可继续移动或缩放。
4. 选区下方 4pt 显示截图确认面板。面板顶部一行左侧显示「我的想法」，右侧显示 `xmark` 取消与 `checkmark` 保存两个图标按钮；原生多行输入框位于标题行下方。面板顶部只保留 4pt 视觉留白，与选区右边缘对齐，宽度优先跟随选区且不小于 320px，空间不足时自动就近调整位置。
5. 完成框选后，焦点自动进入「我的想法」输入框。输入框仍为非必填，但界面不显示「选填」文案；输入框直接使用 AppKit `NSTextView`，支持系统中文输入法、豆包语音流式输入、撤销以及普通文本粘贴，不增加麦克风按钮或语音状态提示。
6. 想法为非必填，最多 20,000 个字符。输入框内 `Enter` 换行，`Command + Enter` 保存；`Esc` 或「取消」关闭遮罩，不写入截图文件、不执行 OCR、不创建卡片。
7. 保存时先隐藏遮罩和确认面板，再截取干净画面，执行本地 Vision OCR，保存原图附件并创建个人记录卡片；输入框内容写入该卡片的「我的想法」，空内容按空字符串保存。
8. 完成后焦点回到截图前的应用，通过 macOS 通知提示「已保存到 IdeaCard」，主窗口不自动打开。

## 标题规则

- 基础标题为 `截图 YYYY-MM-DD HH:mm:ss`，使用用户本地时区。
- 如果数据库已有同名标题，则依次追加 ` (2)`、` (3)` 等后缀。
- 唯一性检查和卡片创建必须在同一条串行保存流程中完成，不引入数据库 schema 变更。

## 原生边界

- 截图选择与确认层由 Swift/AppKit sidecar 实现；React 不承载跨应用覆盖层。
- 原生协议向 Rust 返回 `captured(path, note)` 或 `cancelled`。sidecar 继续复用截图命令响应中的 `text` 字段承载 `note`，不新增通用协议字段；OCR、附件落盘和卡片创建继续由 Rust 编排。
- 截图期间只显示选区、调整点、可选想法输入框以及取消/保存，不增加绘图、文字、橡皮、撤销等标注工具。
- 多显示器下允许在任一显示器开始选择，但单次选区不得跨越显示器。

## 异常与并发

- 屏幕录制权限拒绝：不显示截图层，沿用现有系统设置恢复入口。
- 选区过小：不进入确认态，继续等待用户重新框选。
- 重复触发快捷键：已有截图会话存在时忽略新的触发，不创建并行遮罩。
- 截图或 OCR 失败：清理临时文件，不创建残缺卡片，沿用现有错误提示。
- 取消或保存失败：丢弃本次尚未落卡的想法草稿，不单独保存。
