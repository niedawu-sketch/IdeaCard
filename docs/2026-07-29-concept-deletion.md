# 概念删除

## 目标

用户可以在概念详情中删除一个不再需要的概念及其解释，同时保证引用过该概念的卡片正文仍然完整。

## 交互

- 卡片正文高亮的右键解释浮层在概念标题右侧提供弱化的「查看概念」，进入对应概念详情。
- 概念详情头部显示「删除概念」危险按钮。
- 点击后打开二次确认，展示概念名称和引用数量。
- 确认文案明确说明：概念、概念解释及对应高亮会被移除，卡片文字不会被删除。
- 默认焦点落在「取消」，支持 `Esc` 关闭；删除过程中禁用关闭与重复提交。
- 删除成功后选择列表中的相邻概念；没有剩余概念时展示原有空状态。
- 删除失败时在确认弹窗内显示错误与恢复建议，概念页面保持原状。

## 数据处理

后端新增 `delete_concept` 命令。仓储层在单个数据库事务中：

1. 确认概念存在。
2. 找出所有引用该概念的卡片及结构化正文。
3. 从正文文本节点中移除指向该概念的 mark，并合并相邻同格式文本节点。
4. 校验清理后的正文仍合法，且纯文本投影与删除前完全一致。
5. 更新受影响的 `card_documents`，删除 `concept_mentions` 和 `concepts` 记录。
6. 任一步失败则回滚全部变更。

不修改数据库结构，不删除卡片、附件、可见文字或其他概念。

## 验证

- Rust：覆盖多卡片引用、保留正文与其他 mark、无引用概念、概念不存在和事务回滚。
- TypeScript：覆盖确认文案、取消、失败反馈、成功删除后相邻选择和空状态。
- 端到端：覆盖从概念详情发起删除并返回更新后的概念集合。
