# AI 概念助手设置设计

## 目标

在左下角设置入口中同时提供“模型 API 配置”和“AI 概念助手”两个入口。用户可以修改概念解释使用的 System Prompt，同时应用继续自动提供必要的卡片语境。

## 交互

- 点击左下角设置图标，在图标上方显示紧凑菜单。
- 菜单包含“模型 API 配置”和“AI 概念助手”两个入口。
- “模型 API 配置”沿用现有模型设置弹窗。
- “AI 概念助手”打开独立弹窗，提供 System Prompt 多行输入框、“恢复默认”和“保存”。
- Prompt 不允许为空，最大长度为 8000 个字符。
- “恢复默认”只恢复输入框内容，用户点击“保存”后才持久化。

## Prompt 与上下文

用户编辑的是概念助手的行为规则。概念解释请求自动附加：

- 用户选中的概念；
- 卡片标题；
- 概念所在位置附近的原文。

不再附加“我的想法”和“已保存概念”。附近原文最多 3000 个字符；找不到选中文字时使用原文开头最多 3000 个字符。自动附加的原文被明确标记为参考资料而不是指令。

默认 Prompt：

```text
你是 IdeaCard 的 AI 概念助手。结合当前卡片上下文，准确、简洁地解释用户选中的概念。

先用一句话给出定义，再说明它在当前原文中的具体含义、必要背景和一个简短例子。不要扩写整篇文章，不要偏离选中的概念。使用中文纯文本回答。
```

## 存储

- 使用现有 `app_settings` 表，以独立键 `ai.concept_assistant.v1` 保存。
- 不修改数据库结构，不执行数据迁移。
- 未保存自定义 Prompt 时返回内置默认值。

## 验证

- 后端测试默认值、自定义值持久化、空值和超长值校验。
- AI 请求测试只包含标题和附近原文，不包含“我的想法”和已有概念。
- 前端测试设置菜单双入口、Prompt 加载、保存和恢复默认。
- 完整运行 Rust、React 测试并重新构建签名版 App。
