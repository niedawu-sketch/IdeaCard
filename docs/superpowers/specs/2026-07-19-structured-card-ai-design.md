# 结构化卡片、概念注释与 AI 延伸设计规格

**日期：** 2026-07-19  
**状态：** 已确认  
**确认结论：** 采用方案 A，并允许新增数据库迁移。

## 1. 背景

IdeaCard 当前使用纯文本框保存“原始内容”和“我的想法”，图片只能作为独立附件打开；旧原型中的 AI 以“分析模式”和多卡片材料分析为中心。新的使用诉求不同：

1. 阅读或整理卡片时，选中文字即可让 AI 解释概念。
2. 用户确认解释后，将其沉淀到概念集合，并在原文保留稳定注释。
3. AI 围绕当前卡片延伸想法、归纳和讨论，而不是执行固定的深度分析流程。
4. 正文支持直接粘贴图片，图片出现在光标位置。
5. 支持真实模型接入，至少保证官方 OpenAI，并兼容 OpenAI 格式和 Anthropic Claude。
6. 卡片详情突出原始内容、我的想法和 AI 结果，弱化来源与附件。

## 2. 目标与非目标

### 2.1 目标

- 用结构化正文统一承载文字、图片和概念注释。
- 图片粘贴、附件文件和正文节点保持一一对应，不把图片二进制长期存入 SQLite。
- 概念注释在正文继续编辑后仍绑定正确文字，不使用脆弱的全局字符偏移。
- 解释结果只有在用户确认后才进入概念集合。
- 每张卡片拥有独立 AI 对话，可追问并保存完整结果。
- 提供官方 OpenAI、OpenAI 兼容接口、Anthropic Claude 三种接入方式。
- API Key 只保存到 macOS Keychain。
- 已有卡片和附件在数据库升级后保持可读、可编辑。

### 2.2 非目标

- 不恢复“归纳主题 / 寻找分歧 / 生成建议”等分析模式分类。
- 不实现自动概念抽取、自动标签或自动生成大批知识条目。
- 不实现多人协作、云同步、跨设备同步和模型用量计费统计。
- 不实现复杂富文本格式、表格、代码块、标题层级或 Markdown 工具栏。
- 不要求 OpenAI 兼容服务具备联网搜索；能力由供应商决定。
- 不在本阶段重构或删除旧分析表，避免破坏已有数据兼容性。

## 3. 语音输入结论

2026-07-20 在真实 `.app` 中复测后确认：

- 原生 macOS 输入测试应用可以正常使用豆包语音输入。
- IdeaCard 的普通输入框、多行文本框和结构化正文均无法显示豆包悬浮窗，也无法接收语音文字。
- 关闭全局快捷键监听后问题仍然存在。

当前证据指向豆包输入法与 Tauri/WKWebView 文本输入客户端的兼容性问题。该问题暂缓处理，不阻塞本阶段其他功能；后续优先考虑原生语音输入桥。完整排查记录见 [`docs/2026-07-20-doubao-voice-input-compatibility.md`](../../2026-07-20-doubao-voice-input-compatibility.md)。

## 4. 信息架构

左侧工作区包含：

- 收集箱
- 已归档
- 概念

侧栏底部包含：

- 模型设置
- 本地工作区状态

卡片详情从上到下为：

1. 标题与整理状态。
2. 原始内容。
3. 我的想法。
4. AI 延伸。
5. 默认收起的“来源与附件”。
6. 保存、归档等生命周期操作。

已归档卡片保持只读；概念注释仍可悬浮和跳转，但不能新增或修改。

## 5. 结构化正文

### 5.1 文档格式

正文使用 TipTap / ProseMirror JSON。当前只允许以下节点：

- `doc`
- `paragraph`
- `text`
- `hardBreak`
- `image`

当前只允许以下 mark：

- `concept`

图片节点属性：

```json
{
  "type": "image",
  "attrs": {
    "attachmentId": "UUID",
    "alt": "",
    "title": ""
  }
}
```

新粘贴但尚未持久化的图片可以临时携带 `data` 属性；Rust 保存命令必须在事务提交前将其转换为附件并移除 `data`，SQLite 中不得保留图片 Data URL。

概念 mark 属性：

```json
{
  "type": "concept",
  "attrs": {
    "conceptId": "UUID",
    "mentionId": "UUID"
  }
}
```

### 5.2 兼容纯文本

`cards.original_content` 继续保存结构化正文的纯文本投影，用于：

- 卡片列表摘要。
- 搜索。
- 标题回退。
- 重复内容检测。
- AI 上下文。

`card_documents.document_json` 是编辑与渲染的事实来源。旧卡片首次读取时由 `original_content` 生成只有段落和文字的文档；迁移过程不修改原文字段。

### 5.3 保存规则

- 文本编辑保持现有显式“保存修改”行为。
- 粘贴图片后，图片先在编辑器内即时显示。
- 点击保存时，Rust 同时校验文档、保存新图片附件、替换临时图片节点并更新纯文本投影。
- 任一附件写入或数据库写入失败时，整次保存失败；已写入但未提交的文件必须清理。
- 单张图片最大 20 MB，只接受 PNG、JPEG、HEIC 和 WebP。
- 单次保存最多新增 20 张图片。

### 5.4 图片展示

- 图片在正文光标位置显示。
- 宽度不超过正文可用宽度，高度不超过 520px，保持比例。
- 图片加载失败时显示明确的行内错误和附件名称，不显示空白框。
- 图片通过受控的本地读取命令加载；前端不接触应用附件目录的绝对路径。

### 5.5 快速记录

快速记录中的“记录内容”使用同一结构化编辑器：

- 可以粘贴文字和图片。
- 保存时创建卡片、结构化正文和附件。
- 只有图片没有文字时也允许保存，标题回退为“图片记录”。

## 6. 概念解释与概念集合

### 6.1 发起解释

在可编辑的原始内容中选中非空文字后，应用内右键菜单增加“AI 解释概念”。

- 选区首尾空白会被去除。
- 选区最长 200 个 Unicode 字符。
- 已归档卡片和“我的想法”不显示该动作。
- 发起时保存 ProseMirror 的 `from / to` 选区；AI 返回期间用户修改正文导致选区失效时，要求重新选择，不错误标注其他文字。

### 6.2 解释预览

解释面板显示：

- 概念名称，默认使用选中文字，可修改。
- AI 解释正文。
- “重新生成”“取消”“保存概念”。

发起解释后立即打开预览面板。首个回答字符到达前，解释区显示轻量等待状态；收到首字符后切换为正文，并随模型增量连续追加。生成完成前禁用“保存概念”，取消或请求失败时不保存不完整解释；重新生成会清空旧解释并重新进入等待状态。

AI 解释提示包含：

- 被选中的概念。
- 选区所在段落和必要的卡片上下文。
- 要求用中文解释，先给一句定义，再说明当前语境中的含义。
- 用户开启联网查询且供应商支持时，允许查询。

解释结果在用户点击“保存概念”前不进入数据库。

### 6.3 保存概念

保存操作必须原子完成：

1. 创建或复用同名概念。
2. 创建概念引用 `concept_mentions`。
3. 将概念 mark 写入结构化正文。
4. 更新卡片纯文本投影和更新时间。

同名判断使用去除首尾空白后的 Unicode 大小写不敏感比较。复用已有概念时不自动覆盖其解释；预览面板提示用户正在引用已有概念。

已保存概念允许重新解释，但必须同时满足：选区完整覆盖同一个既有概念标注，并且标注携带的概念 ID、引用 ID 仍与当前卡片数据一致。此时进入显式覆盖模式：

- 概念名称沿用已有名称并只读，不在重新解释时混入重命名语义。
- 预览面板提示「保存后将覆盖原有解释，所有引用此概念的卡片都会显示新解释」。
- 保存动作复用已有概念 ID 和引用 ID，只更新概念解释与更新时间，不新增引用、不重写正文 mark。
- 普通选区即使与已有概念同名，也仍按新增引用处理，不隐式覆盖解释。
- 保存前若原引用、正文或概念身份发生变化，拒绝覆盖并要求重新选择。

### 6.4 原文交互

- 概念文字使用浅绿底和深绿文字。
- 鼠标悬浮只增强概念高亮，不显示解释。
- 右键已保存概念时，在文本操作菜单下方显示独立解释浮层；标题行左侧是概念名称，右侧是小号弱化的“查看概念”入口，解释位于下一行；菜单与浮层作为一个整体保持在视口内。
- 解释浮层超过最大高度时允许在浮层内部滚动；滚动不关闭浮层，也不带动底层卡片。只在点击菜单和浮层之外或按下 `Esc` 时关闭。外部点击由浮层背后的独立透明关闭层承接，不使用 `document` 级命中判断；窗口焦点变化也不得作为关闭条件，以兼容 macOS WKWebView 对原生滚动条事件的重新定向。
- 点击注释进入概念详情。
- 概念详情列出所有来源卡片；点击来源返回对应卡片，并滚动到引用位置。

### 6.5 删除与归档

- 卡片正文的概念高亮通过右键解释浮层提供「查看概念」入口；概念详情提供「删除概念」入口，并在二次确认中显示引用数量。
- 删除概念必须在同一事务内移除概念条目、全部 `concept_mentions`，以及所有结构化正文中指向该概念的 mark；删除 mark 后需要合并相邻同格式文本节点。
- 删除不会移除卡片文字、正文图片或其他概念，也不会改变卡片归档状态。
- 任一卡片正文无法解析或无法确认清理完整时，整个删除操作回滚，概念和所有引用保持原状。
- 归档卡片不删除概念引用；概念详情仍标识来源已归档。
- 永久删除卡片时同步删除该卡片的概念引用、结构化正文、AI 对话和引用数据；概念本身保留。

## 7. 卡片内 AI 延伸

### 7.1 对话边界

每张卡片只有一个连续 AI 对话线程。AI 上下文包含：

- 当前标题。
- 原始内容纯文本。
- 我的想法。
- 当前卡片已引用概念的名称和解释摘要。
- 最近对话消息。

不自动加入其他卡片，也不提供分析模式选择。

### 7.2 交互

- 卡片详情头部显示「AI 延伸」按钮，点击后打开右侧全高抽屉；关闭后归还详情正文空间。
- 抽屉固定宽度上限为 400px，消息区内部滚动，输入框固定在底部。
- 输入框不显示占位提示，使用隐藏标签「和 AI 讨论」提供可访问名称，避免 HTML 代理层与原生输入层文字重叠。
- 用户可输入问题、要求归纳或继续延伸。
- 提供“联网”开关；仅供应商支持时可用。
- 请求中禁用重复发送，允许取消当前请求。
- 发送后立即清空输入框并显示用户消息；AI 回复位置在首字符前显示轻量等待状态，之后按服务端增量连续追加。
- 成功后同时保存用户消息、AI 消息和网页引用。
- 请求失败时保留输入内容，显示可恢复错误，不保存不完整的 AI 消息。

### 7.3 概念解释与对话共用模型

概念解释和卡片对话使用同一个活动模型配置，但提示模板不同。两者共用：

- 连接状态。
- 联网能力判断。
- 统一错误分类。
- Keychain 密钥。

## 8. 模型接入

### 8.1 供应商

支持三类供应商：

1. **OpenAI**
   - 默认地址 `https://api.openai.com/v1`。
   - 默认模型 `gpt-5.6`，用户可修改。
   - 使用 Responses API。
   - 支持官方 `web_search` 工具。
2. **OpenAI 兼容**
   - 用户填写 Base URL 和模型名称。
   - 使用 Chat Completions 兼容格式。
   - 默认不声明联网搜索能力。
3. **Anthropic Claude**
   - 默认地址 `https://api.anthropic.com/v1`。
   - 使用 Messages API。
   - 当前阶段只保证文本生成；联网开关禁用。

### 8.2 流式协议

- 官方 OpenAI Responses 请求启用流式返回，消费 `response.output_text.delta` 文本增量，并从完成事件提取最终正文与引用。
- OpenAI 兼容接口启用 Chat Completions 流式返回，消费 `choices[].delta.content`，以 `[DONE]` 结束。
- Anthropic Messages 请求启用流式返回，消费 `content_block_delta` 中的 `text_delta`。
- Rust 后端负责解析 SSE、校验错误和组装最终结果；前端只接收带 `requestId` 的文本增量，不接触 API Key 或供应商原始响应。
- 取消状态在读取流的过程中检查；取消、网络中断、响应格式错误或未完整结束均视为失败，不写入对话数据库。

### 8.3 设置字段

- 供应商。
- Base URL。
- 模型名称。
- API Key。
- 默认启用联网查询。
- 连接测试。

非密钥设置保存在 `app_settings`。API Key 使用 macOS Keychain：

- service：`com.niedawu.ideacard.ai`
- account：由供应商和规范化 Base URL 的哈希组成。

前端只接收 `hasApiKey`，不得读取或回显已保存密钥。

应用启动、切换卡片和浏览历史 AI 消息时不得访问 Keychain。只有用户打开模型设置、首次激活 AI 输入或发起概念解释时，才按需检查当前供应商的密钥状态，避免应用启动时触发 macOS 钥匙串授权弹窗。

### 8.4 连接测试

- 连接测试使用与真实生成相同的适配器。
- 发送最小请求并要求回复 `OK`。
- 界面明确提示测试会产生一次小额模型调用。
- 鉴权、地址、模型、限流、网络和响应格式错误分别映射为中文错误及恢复建议。
- 错误信息、日志和序列化对象不得包含 API Key、Authorization header 或供应商原始响应正文。

### 8.5 请求安全

- 所有模型请求从 Rust 发起。
- API Key 不写入 SQLite、日志、构建产物、命令行参数或前端持久化。
- Base URL 只允许 `https`；测试环境显式允许回环地址的 `http`。
- 请求设置连接和总超时。
- 响应体设置大小上限。
- AI 输出只作为文本渲染，不执行 HTML。

## 9. 数据模型与迁移

新增 `0002_structured_card_ai.sql`，数据库版本从 1 升到 2。

### 9.1 `card_documents`

- `card_id`：主键，引用 `cards.id`。
- `document_json`：结构化正文 JSON。
- `schema_version`：当前为 1。
- `updated_at`。

### 9.2 `card_document_images`

正文图片与附件的对应关系保存在 `card_document_images`：

- `card_id`。
- `attachment_id`。
- `position`。
- 同一正文中附件唯一。

该表用于校验图片归属，并在用户从正文删除图片时安全清理对应附件文件。

### 9.3 `concepts`

- `id`。
- `name`。
- `normalized_name`：唯一。
- `explanation`。
- `created_at`。
- `updated_at`。

### 9.4 `concept_mentions`

- `id`。
- `concept_id`。
- `card_id`。
- `selected_text`。
- `created_at`。

正文 mark 通过 `mentionId` 与该表对应。

### 9.5 `card_ai_threads`

- `id`。
- `card_id`：唯一。
- `created_at`。
- `updated_at`。

### 9.6 `card_ai_messages`

- `id`。
- `thread_id`。
- `role`：`user` 或 `assistant`。
- `content`。
- `created_at`。

### 9.7 `card_ai_citations`

- `message_id`。
- `url`。
- `title`。
- `position`。

### 9.8 迁移要求

- 版本 1 数据库在单个事务中升级到版本 2。
- 新安装直接依次应用 0001 和 0002。
- 迁移失败时保留原数据库文件，不创建空白替代库。
- 启动时校验版本、表、索引、外键和关键约束。
- 迁移测试必须使用真实版本 1 数据库并证明原卡片、附件和旧分析记录不变。

## 10. 错误处理

必须提供稳定错误码：

- `document_invalid`
- `document_too_large`
- `inline_image_invalid`
- `inline_image_too_large`
- `concept_selection_stale`
- `concept_not_found`
- `ai_not_configured`
- `ai_key_unavailable`
- `ai_auth_failed`
- `ai_model_not_found`
- `ai_rate_limited`
- `ai_network_failed`
- `ai_response_invalid`
- `ai_request_cancelled`

用户输入、正文草稿和 AI 提问在可恢复错误后保持不变。

## 11. 验收标准

1. 版本 1 数据库升级后原卡片、附件和旧分析数据完整。
2. 旧纯文本卡片可直接以结构化正文打开和保存。
3. 快速记录和卡片正文都能在光标位置粘贴图片。
4. 保存后重启应用，图片仍显示在原位置，SQLite 不含图片 Data URL。
5. 选中文字可通过右键发起 AI 解释。
6. 未确认的解释不会进入概念集合。
7. 保存概念后，右键可在文本菜单下方查看解释，点击高亮文字可进入概念详情。
8. 概念详情可跳回来源卡片及对应引用。
9. 卡片内可连续追问，成功消息重启后仍存在。
10. OpenAI、OpenAI 兼容和 Claude 请求分别通过协议级模拟服务测试。
11. 官方 OpenAI 设置支持连接测试和联网开关。
12. API Key 只进入 Keychain；数据库、日志和构建产物扫描无密钥。
13. 详情页主要空间用于原始内容、我的想法和 AI 延伸；来源与附件默认收起。
14. 已归档卡片只读，概念注释可查看但不可新增。
15. 豆包语音输入当前列为已知兼容性问题，不作为本阶段验收通过条件；后续按独立方案处理。
