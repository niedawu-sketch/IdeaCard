# IdeaCard Mac MVP 设计规格

## 1. 文档目的

本文档定义 IdeaCard 从可交互网页原型进入可实际使用的 Mac 桌面产品阶段后的产品范围、技术架构、系统能力、数据结构、AI 行为、权限边界、异常处理和验收标准。

本阶段的交付物是一个可在当前 Mac 本地安装和运行的 `.app`。首版不处理开发者签名、公证、自动更新、Mac App Store 上架和对外分发。

## 2. 产品目标

IdeaCard 帮助用户把阅读材料、临时问题和个人想法快速沉淀为可继续思考的卡片，并在用户主动选择上下文后，借助 AI 延伸想法、查询不清楚的信息和形成可追溯结论。

MVP 必须完成以下真实闭环：

1. 通过全局快捷键、剪贴板、截图或文件导入捕获材料。
2. 自动把材料放入统一收集箱，不要求用户在捕获时完成整理。
3. 保留原始材料和“我的想法”，允许后续补充和修正来源。
4. 用户选择一至二十张卡片，提出想延伸或查询的问题。
5. AI 基于所选卡片回答，并按需联网搜索，展示卡片引用和网页引用。
6. 用户继续追问或把有价值的结果保存为结论。
7. 应用重启后，卡片、附件、分析会话和结论仍可使用。

## 3. 已确认决策

- 交付范围：只保证在当前 Mac 本地安装和使用。
- 桌面技术：Tauri 2、React、TypeScript、Rust，配合小型 Swift 原生辅助模块。
- 系统范围：最低支持 macOS 14，只验证当前 Mac。
- 数据策略：本地优先，不提供账号、云同步或多人协作。
- AI 服务：首版只接 OpenAI Responses API。
- AI 密钥：存入 macOS Keychain，不写入数据库、日志、前端状态或构建产物。
- 用户可见来源分类：个人记录、文档资料。底层旧值继续兼容读取，但不再作为界面选项。
- 标签：MVP 不提供标签能力。
- 已批准操作：安装用户级 Rust 工具链，创建 IdeaCard 初始 SQLite 数据结构。

## 4. MVP 范围

### 4.1 桌面入口

应用包含三类入口：

- 菜单栏入口：显示快速记录、剪贴板捕获、截图捕获、打开主窗口和退出。
- 主窗口：承载收集箱、卡片详情、AI 延伸工作台、结论和设置。
- 全局快捷键：分别触发快速记录、剪贴板捕获和截图捕获。

首版使用固定快捷键：`Control+Option+Space` 打开快速记录，`Control+Option+V` 捕获剪贴板，`Control+Option+S` 开始截图。注册失败或与其他应用冲突时，应用明确提示冲突，但主窗口和菜单栏入口仍可正常使用。快捷键自定义不进入 MVP。

主窗口隐藏标准标题栏后，顶部替代区可以直接拖动；工作区其余空白区域在鼠标左键持续按住约 260ms 后进入原生窗口拖动，以支持在多显示器之间移动。长按成立前移动超过 6px即取消。所有按钮、链接、输入框、富文本、卡片、文字内容、菜单和弹窗都不参与该手势，保持原有点击、选择、滚动和输入行为。

### 4.2 快速记录

快速记录窗口只包含完成捕获所需的字段：

- 标题：允许为空；保存时取内容第一行，压缩连续空白后截取前三十个字符作为标题，内容仍为空时不允许保存。
- 记录内容：必填。
- 我的想法：选填。

保存后生成“个人记录”来源的卡片并关闭快速记录窗口。纯文本记录目标是在五秒内完成。

### 4.3 剪贴板捕获

剪贴板只在用户点击入口或触发快捷键时读取，不后台监听。

- 文字：生成可确认的捕获草稿。
- 网址：保留网址并归入“文档资料”。
- 图片：保存图片附件，执行本地 OCR，并归入“个人记录”。
- 空内容或不支持的内容：不创建卡片，明确说明原因。

普通剪贴板文字无法可靠判断原始载体时，默认归入“个人记录”。用户可在卡片详情中修正来源类型和具体来源。

### 4.4 截图与 OCR

用户触发截图后选择屏幕区域，应用保存原图附件并使用 macOS Vision 在本地识别文字。

- OCR 成功：识别文本写入卡片原始内容，原图作为附件保留。
- OCR 未识别到文字：仍保存图片卡片，提示用户可手工补充内容。
- 截图取消：不创建卡片。
- 权限被拒绝：保留当前操作意图，并提供打开系统设置的入口。

截图卡片固定归入“个人记录”。

### 4.5 文件导入

文件必须由用户通过系统文件选择器主动选择。应用把选中文件复制到自己的 Application Support 目录，后续不依赖原始文件位置。

MVP 支持以下文件：

| 文件类型 | 处理方式 | 来源类型 |
| --- | --- | --- |
| PDF | 提取可复制文字；无文字页允许继续保存 | 文档资料 |
| Word | 提取正文文字 | 文档资料 |
| PowerPoint | 按幻灯片顺序提取文字 | 文档资料 |
| Excel | 按工作表提取非空单元格文字 | 文档资料 |
| Markdown、TXT | 按文本读取 | 文档资料 |
| PNG、JPEG、HEIC | 保存原图并执行 Vision OCR | 文档资料 |
| 音频、视频 | 保存文件和基本信息，不转写 | 文档资料 |

文件提取失败时不丢弃原文件。卡片展示失败原因，并允许用户补充“我的想法”、重新提取或归档。

单次最多选择二十个文件。文档或图片单文件不超过 50 MB，音视频单文件不超过 500 MB；超过时不复制文件并明确提示限制。提取后的完整文字保存在本地，不因 AI 上下文限制而截断。

### 4.6 收集箱与卡片处理

主窗口沿用已验证的三栏结构：

- 左栏：工作区导航和两类来源筛选。
- 中栏：搜索、捕获入口、卡片列表和批量选择。
- 右栏：原始内容、附件、来源信息、我的想法、状态和操作。

收集箱支持：

- 搜索标题、原始内容和我的想法。
- 按“个人记录、文档资料”两类来源筛选。
- 编辑标题、原始内容和我的想法。
- 修正来源类型、来源名称和来源地址。
- 标记待分析、归档和恢复归档。
- 选择一至二十张卡片创建 AI 上下文。
- 从卡片打开应用内部保存的附件。

MVP 不提供标签、文件夹、知识图谱、双向链接和自动主题分类。

### 4.7 AI 延伸与查询

AI 工作台不提供“归纳主题”“寻找分歧”等模式分类。用户只需要填写一个问题，并决定是否允许联网查询。

一次 AI 会话包含：

- 会话标题。
- 一至二十张上下文卡片。
- 用户问题。
- 联网查询开关，默认开启。
- 用户和 AI 的连续消息。
- 卡片引用和网页引用。
- 运行、完成、失败或取消状态。

默认回答组织为：

1. 直接回应。
2. 可延伸方向。
3. 查询到的补充信息。
4. 下一步行动。
5. 尚未解决或需要确认的问题。

回答以流式方式展示。用户可以取消、重试、继续追问，并把当前有效结果保存为结论。取消或网络中断时不把残缺输出保存为正式 AI 消息，但原问题和上下文保持不变。

发起请求前计算所选卡片标题、原始内容和我的想法的总字符数。超过 200,000 个 Unicode 字符时阻止请求，列出占用最大的卡片并要求用户减少材料或缩短内容；应用不得静默截断材料。

### 4.8 结论

保存的结论包含：

- 标题和原始问题。
- 用户确认保存的 AI 回答。
- 相关追问。
- 卡片引用。
- 网页引用。
- 创建时间。

用户可以从结论返回来源卡片，也可以基于原会话继续追问。删除结论不进入 MVP。卡片可从收集箱或已归档工作区在二次确认后永久删除；存在 AI 会话或结论引用时拒绝删除。

### 4.9 设置

设置页包含：

- 添加、更新和移除 OpenAI API Key。
- 测试 OpenAI 连接。
- 展示截图权限状态并打开对应系统设置。
- 展示三个固定全局快捷键及其注册状态。
- 展示本地数据目录和应用版本。

MVP 不提供多模型供应商、模型参数调节、代理配置、云同步和自动更新。

## 5. 技术架构

### 5.1 总体结构

```text
React 产品界面
    ↓ 类型化桌面服务接口
Tauri / Rust 应用核心
    ├── SQLite 数据仓库
    ├── Application Support 附件仓库
    ├── 全局快捷键与菜单栏
    ├── 剪贴板与文件导入
    ├── OpenAI Responses API 客户端
    └── Swift 原生辅助模块
         ├── Vision OCR
         ├── 截图
         └── macOS Keychain
```

### 5.2 前端职责

React 前端负责：

- 页面和窗口交互。
- 表单状态与输入校验。
- 卡片、会话和结论的展示状态。
- 流式 AI 事件的界面更新。
- 将所有桌面能力通过统一服务接口调用。

前端不得直接访问 SQLite、附件目录、Keychain 或 OpenAI API。浏览器原型中的 `localStorage` 持久化在桌面应用中由仓库接口替代。

### 5.3 Rust 应用核心职责

Rust 核心负责：

- Tauri 生命周期、窗口、菜单栏和全局快捷键。
- 参数校验和统一错误类型。
- SQLite 事务、查询和迁移。
- 附件复制、命名、校验和读取。
- 文件类型识别与提取流程编排。
- 调用 Swift 原生辅助模块。
- OpenAI 请求、流式解析、取消和错误映射。
- 向前端暴露最小化、类型明确的命令和事件。

### 5.4 Swift 原生辅助模块职责

Swift 模块以随 `.app` 打包的 `IdeaCardNative` 辅助可执行文件提供 macOS 专属能力：

- 使用 Vision 识别图片文字。
- 触发并获取区域截图结果。
- 使用 Security/Keychain Services 保存、读取和移除 API Key。

Swift 模块不包含卡片、分析或结论业务规则。Rust 通过子进程调用它，使用标准输入和标准输出交换受控 JSON，并把原生错误转换为应用错误。API Key 不通过命令行参数传递，辅助进程不得把密钥写入标准错误或日志。

### 5.5 模块边界

建议代码结构：

```text
desktop/
├── src/                       # React 产品界面
│   ├── app/                   # 路由、窗口级编排
│   ├── entities/              # 卡片、会话、结论类型
│   ├── features/              # 捕获、收集箱、AI、设置
│   ├── services/desktop/      # 类型化桌面服务接口
│   └── shared/                # UI、错误和通用工具
├── src-tauri/
│   ├── src/
│   │   ├── commands/          # Tauri 命令薄层
│   │   ├── domain/            # 领域类型和规则
│   │   ├── repository/        # SQLite 与附件仓库
│   │   ├── capture/           # 剪贴板、截图、文件导入编排
│   │   ├── ai/                # OpenAI 客户端与流式事件
│   │   ├── native/            # Swift 辅助模块适配
│   │   └── app_error.rs       # 统一错误模型
│   ├── migrations/            # 顺序且不可变的 SQLite 迁移
│   └── native/                # Swift 源码与构建配置
└── tests/                     # 桌面端到端验收
```

原有 `prototype/` 继续作为产品交互参照，不直接改造成桌面工程。桌面产品位于独立 `desktop/`，按已验证的界面和领域概念逐步迁移，避免把模拟适配器和浏览器持久化带入正式产品。

- SQLite：`Application Support/IdeaCard/ideacard.sqlite3`
- 附件：`Application Support/IdeaCard/attachments/`

- API Key：macOS Keychain

数据库只保存附件相对路径。附件文件名使用应用生成的稳定标识，不直接使用用户文件名作为磁盘主键。

### 6.3 数据规则

- 所有标识使用应用生成的唯一字符串。
- 时间统一以 UTC ISO 8601 或数据库整数时间保存，界面按本地时区显示。
- `source_type` 只允许五个稳定英文值：`personal`、`web`、`document`、`image`、`media`。
- `capture_method` 描述采集方式，不作为来源分类。
- `capture_method` 只允许 `quick`、`clipboard`、`screenshot`、`file`。
- 卡片状态只允许 `unprocessed`、`annotated`、`pending_analysis`、`concluded`、`archived`。
- 附件提取状态只允许 `pending`、`completed`、`empty`、`failed`、`not_applicable`。
- 分析会话状态只允许 `draft`、`running`、`completed`、`failed`、`cancelled`。
- 消息角色只允许 `user`、`assistant`；只有完整消息写入 `analysis_messages`。
- 新卡片根据去除首尾空白后的内容哈希、附件校验值或相同来源地址判断重复。
- 检测到重复时提示用户，但不自动阻止保存。
- 单个分析会话最多关联二十张卡片。
- SQLite 外键保持开启，跨表写入使用事务。
- 初始结构通过版本化迁移创建；迁移文件一旦发布后不可改写。
- `insight_messages` 在保存时固定本次结论包含的消息范围；后续追问不会改变已经保存的结论。
- MVP 不提供卡片、附件、分析会话和结论的删除操作，不设计业务数据级联删除。移除 API Key 是独立的安全设置操作，不删除业务数据。

## 7. AI 与隐私设计

### 7.1 请求边界

只有用户主动发起 AI 延伸或追问时，应用才发送数据。请求只包含：

- 当前用户问题。
- 当前会话中用户明确选择的卡片标题、原始内容和我的想法。
- 为维持追问所需的本地历史消息。
- 联网查询开关。

附件文件默认不直接上传。PDF、Office 和图片使用本地提取后的文字作为上下文。音视频没有本地转写时，只发送用户补充的文字和文件基本信息。

### 7.2 OpenAI 调用

- 使用 Responses API。
- 默认模型为 `gpt-5.4-mini`，首版不提供模型切换。
- 请求设置 `store: false`。
- 允许联网时提供 `web_search` 工具；关闭时不向请求加入该工具。
- 使用流式响应更新界面。
- 不使用 OpenAI Conversations 保存会话状态。
- 追问时由本地数据库重新组装必要上下文。
- 每张上下文卡片按选择顺序获得稳定标签 `C1`、`C2` 等；提示词要求使用 `[C1]` 形式引用。Rust 只把本次上下文中可解析的标签转换为卡片引用，不接受模型生成的任意卡片标识。
- 记录用于排障的请求标识和错误类别，但不记录 API Key、完整请求正文或完整响应正文。

`store: false` 不代表服务方绝不短期保留内容。设置页必须说明：用户选择的材料会发送给 OpenAI，OpenAI 默认可能保留滥用监控日志；具体规则以用户 OpenAI 账户的数据控制策略为准。

### 7.3 引用

- 卡片引用使用应用内部卡片标识，点击后定位到卡片详情。
- 网页引用保存标题、URL 和响应中的文本位置，点击后使用系统默认浏览器打开。
- AI 未提供可验证来源时，界面不得伪造网页引用。

## 8. 权限与安全

- 截图时才请求屏幕录制权限。
- 文件访问只发生在用户主动选择文件后。
- 剪贴板只在明确操作时读取，不后台监听。
- API Key 使用 Keychain 加密存储，并提供显式移除能力。
- 前端 WebView 不获得任意文件系统、Shell 或网络权限。
- Tauri capability 只开放实际需要的命令和插件权限。
- 所有文件路径在 Rust 侧规范化并校验，不接受前端拼接的任意写入路径。
- 导入文件写入临时文件后进行校验，再原子移动到附件目录。
- 日志默认不包含用户原始内容、我的想法、附件正文或 API Key。
- 对外错误只包含稳定错误码、中文提示和恢复动作；SQLite、文件系统与系统 API 的原始错误文本不得进入前端状态、日志或序列化响应，避免暴露 SQL、内部路径和系统细节。
- MVP 不申请麦克风、摄像头、通讯录、辅助功能或全盘访问权限。

## 9. 异常与恢复

### 9.1 捕获异常

- 快捷键冲突：显示冲突入口，菜单栏和主窗口仍可捕获。
- 剪贴板为空：不创建卡片。
- 截图取消：不显示错误，不创建卡片。
- 截图权限拒绝：说明影响并提供系统设置入口。
- OCR 失败：保存图片卡片和原图，允许补充内容或重试。
- 文件损坏或格式不支持：保存原文件和失败原因，允许归档或重试。
- 文件数量或大小超过限制：不复制超限文件，显示具体限制。
- 附件复制失败：不创建不完整卡片，清理本次临时文件。

### 9.2 数据异常

- 数据库打开失败：阻止写入并显示数据目录，不创建第二份空数据库覆盖原文件。
- 迁移失败：事务回滚，保留原数据库，阻止进入可能损坏数据的主界面。
- 附件丢失：卡片继续可见，附件区域显示缺失状态。
- 重复材料：提示已有卡片，用户仍可继续保存。

### 9.3 AI 异常

- 未配置 API Key：直接进入设置，不发起请求。
- Key 无效或额度不足：区分错误类型并提供重新测试入口。
- 网络超时或服务错误：保留问题和上下文，允许重试。
- 流式响应中断：丢弃残缺的正式回答，保留可诊断错误状态。
- 用户取消：停止请求，不保存残缺回答。
- 联网查询失败：保留会话并允许关闭联网后重试。
- AI 上下文超过 200,000 字符：不发起请求，展示占用最大的卡片。

## 10. 测试策略

- 来源映射、重复判定和分析上限单元测试。
- SQLite 仓库、事务、外键和初始迁移测试。
- 附件复制、校验、原子移动和失败清理测试。
- 文件类型识别与提取编排测试。
- OpenAI 请求构造、流式事件解析、取消和错误映射测试。
- Keychain 和原生能力通过接口替身测试业务行为。

### 10.3 原生模块测试

- 使用固定中文和英文图片验证 Vision OCR。
- 验证截图成功、取消和权限拒绝结果。
- 验证 Keychain 新增、读取、更新和移除。

### 10.4 桌面端验收

- 构建真实 `.app` 并在当前 Mac 启动。
- 在打包应用中测试菜单栏和全局快捷键。
- 完成快速记录、剪贴板、截图 OCR 和每类文件导入。
- 退出并重新打开应用，核对持久化数据和附件。
- 使用真实 OpenAI API 完成一次流式延伸、一次联网查询、一次追问和一次结论保存。
- 验证无 API Key、权限拒绝、OCR 失败、文件损坏、快捷键冲突和 AI 请求失败。
- 检查数据库、日志、前端状态和构建产物中不存在 API Key。

## 11. 验收标准

1. 当前 Mac 上可以生成、安装和启动 IdeaCard `.app`。
2. 菜单栏入口和三个全局快捷入口可用，冲突时有明确降级路径。
3. 用户能在五秒内完成一次纯文本快速记录。
4. 剪贴板文字、网址和图片能生成对应卡片。
5. 区域截图能保存原图并使用 Vision 生成或尝试生成 OCR 文本。
6. PDF、Word、PowerPoint、Excel、Markdown、TXT、图片和音视频文件能导入；支持的文档能提取文字，失败时保留原文件。
7. 所有卡片进入统一收集箱，可按五类来源筛选，界面不出现标签能力。
8. 卡片明确区分原始内容和我的想法，并可修正来源信息。
9. 用户能选择一至二十张卡片发起真实 AI 延伸，控制是否联网，查看流式结果、卡片引用和网页引用。
10. 用户能取消、重试、连续追问并保存结论。
11. 应用重启后，卡片、附件、分析会话和结论完整存在。
12. API Key 只存在于 Keychain，不出现在 SQLite、日志、前端状态或构建产物中。
13. 权限、捕获、文件、数据库和 AI 的主要失败场景均有可恢复路径。
14. 自动测试、真实系统能力验收和 `.app` 打包验证全部通过。

## 12. MVP 不做

- 开发者签名、公证、DMG、自动更新和公开分发。
- Mac App Store 上架和 App Sandbox 适配。
- Windows、移动端和 Web 正式版。
- 账号、云同步、多人协作和数据共享。
- 浏览器扩展、微信公众号专用插件和后台剪贴板监听。
- 音频或视频转写。
- 标签、文件夹、双向链接和知识图谱。
- 多模型供应商和本地模型。
- 快捷键自定义。
- 删除结论。
- 自动备份、导入导出和旧原型 `localStorage` 数据迁移。

## 13. 实施顺序

1. 整合已经确认的原型来源分类和 AI 延伸行为，形成桌面产品基线。
2. 建立 `desktop/` Tauri 工程、测试环境和类型化桌面服务边界。
3. 建立 SQLite 初始迁移、附件仓库和卡片业务。
4. 实现主窗口、菜单栏、快速记录、剪贴板和全局快捷键。
5. 实现文件导入、截图和 Vision OCR。
6. 实现 Keychain 设置和 OpenAI Responses API 流式调用。
7. 实现 AI 追问、引用和结论保存。
8. 完成异常恢复、自动测试、真实系统验收和 `.app` 打包。
