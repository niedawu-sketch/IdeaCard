# IdeaCard 文本右键菜单精简设计

> 状态：已确认（2026-07-19）

## 1. 目标

macOS WebView 默认右键菜单包含查词、翻译、搜索、拼写、字体、语音、共享、开发者检查、自动填充和系统服务等大量选项。它们不是 IdeaCard MVP 的核心能力，会让文本整理界面显得复杂。

本次用应用自己的中文菜单替换系统默认菜单，只保留文字编辑所需的基本操作。

## 2. 已选方案

采用自定义应用内右键菜单。

曾考虑以下方案：

- 仅禁用系统菜单：最简单，但用户会失去鼠标复制和粘贴能力。
- 保留系统菜单：无需开发，但无法满足 MVP 简洁要求。
- 自定义基础菜单：开发量适中，可以稳定控制选项、文案和状态。本次采用此方案。

## 3. 菜单内容

在可编辑的单行输入框和多行输入框中显示：

1. 剪切
2. 复制
3. 粘贴
4. 全选

在普通只读文字上存在选区时，只显示：

1. 复制

其他区域右键不显示菜单。

不再显示查词、翻译、网页搜索、拼写与语法、替换、转换、字体、语音、段落方向、共享、检查元素、自动填充和系统服务。

## 4. 状态规则

- 没有选中文字时，剪切和复制不可用。
- 输入框为只读或禁用状态时，不显示剪切和粘贴。
- 剪贴板中没有文字时，粘贴不可用。
- 全选在输入框存在文字时可用。
- 菜单项执行后立即关闭。
- 点击菜单外部、按 `Esc`、窗口滚动或失去焦点时关闭。

## 5. 交互与视觉

- 菜单出现在鼠标位置附近，并始终完整留在窗口内。
- 使用现有弹层颜色、边框、圆角和阴影，不引入新的视觉 token。
- 菜单使用中文短文案，不显示说明性文字。
- 不影响 `Command+C`、`Command+X`、`Command+V` 和 `Command+A` 等系统快捷键。

## 6. 技术边界

- 应用根节点统一拦截 WebView 的 `contextmenu` 事件，防止系统完整菜单出现。
- 前端保存当前文本选区，并通过桌面服务读写系统纯文本剪贴板。
- 剪切和粘贴修改输入框后触发标准输入事件，继续走 React 现有受控表单逻辑。
- 剪贴板读写失败时关闭菜单并显示可恢复的行内错误，不静默吞掉失败。
- 不处理富文本格式、图片粘贴、拼写建议和网页搜索。

## 7. 验收标准

1. 在卡片标题、原始内容、来源信息、我的想法和捕获输入框中右键，只出现剪切、复制、粘贴、全选。
2. 普通文字选区右键只出现复制。
3. 系统默认完整菜单和“检查元素”不再出现。
4. 不可用操作具有明确禁用状态。
5. 菜单不会超出 1100×700 的最小窗口。
6. 鼠标操作和现有键盘快捷键都能正确修改受控输入内容。
7. 前端测试、Rust 剪贴板测试、布局 E2E 和 Mac `.app` 验证通过。
