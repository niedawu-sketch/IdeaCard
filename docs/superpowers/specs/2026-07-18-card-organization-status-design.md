# IdeaCard 卡片整理状态设计

## 1. 目标

卡片状态只回答一个问题：这张卡片是否已经被用户整理过。

界面仅显示两个状态：

- `待整理`：新捕获的卡片，尚未补充个人想法。
- `已整理`：用户已经补充并保存了非空的“我的想法”。

状态由用户操作自动变化，不允许用户通过下拉框直接设置。

## 2. 状态变化

### 新建卡片

通过快速记录、剪贴板、截图或文件导入创建的卡片，初始状态为`待整理`。

### 完成整理

`待整理`卡片保存非空的“我的想法”后，自动变为`已整理`。

保持现有行为：

- 仅打开、浏览或选择卡片不改变状态。
- 只修改标题、正文、来源类型、来源名称或来源地址不改变状态。
- 已经进入`已整理`的卡片，之后清空“我的想法”也不自动退回`待整理`。

## 3. AI 与归档

AI 延伸属于整理过程中的可选操作，不是卡片生命周期的必经环节，因此：

- 不显示`待分析`。
- 不显示`已生成结论`。
- 不因选择 AI 材料、提交 AI 请求或生成结论改变卡片整理状态。

归档只是一项存放操作，因此：

- 不把`已归档`作为卡片整理状态展示。
- 归档入口和归档筛选后续独立表达。

## 4. 兼容策略

本次不修改数据库结构，也不迁移现有数据。

底层历史状态按以下规则映射到界面：

| 底层状态 | 界面显示 |
| --- | --- |
| `unprocessed` | 待整理 |
| `annotated` | 已整理 |
| `pending_analysis` | 已整理 |
| `concluded` | 已整理 |
| `archived` | 不在普通收集箱展示 |

底层状态枚举和状态更新能力暂时保留，供现有归档逻辑和历史数据兼容使用；用户界面不再提供直接修改状态的控件。

## 5. 界面修改

- 卡片列表只显示`待整理`或`已整理`。
- 卡片详情把状态下拉框改成只读状态展示。
- 状态展示继续使用现有状态点和文字，不增加说明性文案。
- 归档卡片不在普通收集箱中出现，不额外显示归档状态。

## 6. 验收标准

- 用户无法在卡片详情中手动选择状态。
- 新建卡片显示`待整理`。
- 待整理卡片保存非空“我的想法”后显示`已整理`。
- 打开卡片或修改非“我的想法”字段不会改变整理状态。
- 界面不再出现`待分析`、`已生成结论`或`已归档`状态。
- 历史 AI 状态卡片仍可正常显示，并统一呈现为`已整理`。
- 不涉及数据库 schema 变更或数据迁移。
