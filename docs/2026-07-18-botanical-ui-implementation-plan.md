# IdeaCard「标本工作台」视觉重构实施计划

## 1. 目标

把 `desktop/` 当前灰白、低对比的界面统一为 `PRODUCT.md` 与 `DESIGN.md` 已确认的「标本工作台」方向：

- 左侧应用导航与来源筛选形成有分量的中绿 chrome（界面框架）。
- 卡片列表、详情、表单和弹层保持明亮、适合长时间阅读的近白工作区。
- 深墨绿只承担主操作、链接与焦点状态。
- 保留现有收集、筛选、捕获、编辑和附件交互，不改变业务行为。

高保真参照物：

- `.superpowers/ui-style-exploration/out/j-botanical.html`
- `.superpowers/ui-style-exploration/out/j-botanical.png`
- `.superpowers/ui-style-exploration/themes/j-botanical.css`

设计事实来源：

- `PRODUCT.md`
- `DESIGN.md`

## 2. 修改边界

### 进入本次范围

- 应用壳、品牌区、左侧导航和本地工作区状态。
- 来源筛选栏的 chrome 配色、反白选中态与来源色点。
- 搜索框、结果计数、捕获入口、刷新与菜单按钮。
- 卡片列表的文字层级、状态点、悬停态和内缩圆角高亮选中态。
- 卡片详情、字段、附件、保存操作和空状态。
- 快速记录、捕获确认、捕获菜单、文件导入结果、错误和重复提示。
- 焦点、禁用、加载、错误及减少动效状态。

### 不进入本次范围

- 不新增导航页面或伪造尚未实现的功能。
- 不调整卡片、捕获、附件或 Store 的数据结构。
- 不修改 Tauri、Rust、Swift、数据库或系统能力。
- 不改变三栏信息架构和现有交互流程。
- 不把风格探索目录中的静态 HTML 直接复制成业务组件。

## 3. 预计修改文件

### 必改

- `desktop/src/shared/styles/global.css`
  - 用 `DESIGN.md` 的 OKLCH token 替换当前颜色体系。
  - 对齐字号、圆角、描边、状态色、按钮、字段、弹层和动效规则。
  - 移除卡片选中态的描边和左侧色条，改为内缩圆角高亮底色。

- `desktop/src/pages/InboxPage.tsx`
  - 仅增加来源类型的语义样式钩子，用于五种来源色点。
  - 不改变筛选逻辑、捕获逻辑和页面结构。

### 视实现结果决定

- `desktop/src/app/App.tsx`
  - 只有在现有结构无法表达已确认的品牌区或状态样式时，补充最小语义类名。

- `desktop/src/features/inbox/CardList.tsx`
- `desktop/src/features/inbox/CardDetail.tsx`
- `desktop/src/features/capture/*.tsx`
  - 原则上只使用现有类名完成换肤。
  - 只有缺少必要状态钩子时才增加类名或 `data-*` 属性，不改业务逻辑。

- `DESIGN.md`
  - 仅当浏览器实测迫使 token 微调时同步修改，并记录调整原因。

## 4. 实施步骤

### 步骤一：建立 token 与全局基础

1. 把 `DESIGN.md` 第 2 节 token 写入 `:root`。
2. 统一系统字体、等宽元信息字体、固定字号阶梯和圆角。
3. 统一 focus-visible、disabled 和 reduced-motion。
4. 用语义 token 替换散落的十六进制灰色、绿色和边框色。

验收：

- 工作区无暖米色、奶油色或无意义灰阶。
- 正文、摘要、元信息和主按钮达到规定对比度。
- 不引入渐变、毛玻璃、发光或装饰性投影。

### 步骤二：重构绿色 chrome

1. 应用侧栏使用 `--chrome`。
2. 来源栏使用 `--chrome-raised`。
3. 品牌、导航、标签和底部状态分别使用三档 chrome 文字色。
4. 导航与来源当前项统一使用反白选中态。
5. 五种来源通过语义色点区分，不使用彩色标签块。

验收：

- chrome 绿占据左侧 30–40% 视觉表面，内容区仍然明亮。
- 灰色文字不直接放在绿色背景上。
- 导航和筛选选中态形制一致。

### 步骤三：统一工作区组件

1. 搜索框、字段和次按钮统一为白底、强分隔线和 7px 圆角。
2. 主按钮统一使用 `--accent` 与 `--accent-text`。
3. 工具栏、列表和详情只使用 1px 发丝线分区。
4. 卡片列表保持“列表项”结构，不改成卡片网格。
5. 计数、时间和 MIME 类型切换到等宽元信息字体。

验收：

- 同一操作在不同弹层和页面中保持同一按钮形制。
- 表单 default、hover、focus、disabled 和 error 状态清楚。
- 不产生卡片套卡片或过度圆角。

### 步骤四：强化选择与状态

1. 卡片选中态改为向内缩进 3px 的 `--selection-fill` 圆角高亮，不使用描边。
2. 卡片只显示“待整理 / 已整理”，使用 5px 圆点和对应语义文字色。
3. 警告、错误和重复提示改用设计系统功能色。
4. 加载继续保留现有行为，但视觉反馈遵守动效和减少动效规则。

验收：

- 不存在 `border-left > 1px` 或模拟侧边色条的选中态。
- 状态颜色不是唯一信息来源，仍保留文字。
- 选中、悬停、焦点三种状态可以同时被辨认。

### 步骤五：覆盖弹层与异常状态

1. 快速记录、捕获确认、捕获菜单和导入结果统一到新 token。
2. 弹层允许使用设计规范中的唯一投影。
3. 错误与重复提示保持行内，不扩大为模态框。
4. 空列表和空详情继续告诉用户下一步动作。

验收：

- 弹层不出现旧灰绿样式残留。
- 捕获流程的正常、失败、取消和重复提示均可读。

### 步骤六：视觉与工程验证

依次运行：

```bash
cd desktop
npm run build
npm run lint
npm test
npm run test:e2e -- e2e/inbox-layout.spec.ts
```

另外执行：

```bash
node ../.superpowers/ui-style-exploration/check-contrast.mjs
```

并在以下窗口尺寸截图检查：

- 1100 × 700：最低支持尺寸，无横向溢出、按钮重叠或详情字段截断。
- 1280 × 800：标准桌面尺寸，三栏比例和内容密度接近高保真稿。
- 1440 × 900：宽屏下详情区不会空泛，列表不会过窄。

视觉检查重点：

- `j-botanical.png` 的绿柜/白工作台比例。
- 所有文字对比度与焦点可见性。
- 卡片内缩圆角高亮选中态。
- 捕获菜单和导入结果不被容器裁剪。
- 无渐变、毛玻璃、发光、侧边强调条和暖米色。

## 5. 回归风险与控制

- **最小宽度风险**：chrome 加深后视觉重量增加，但不扩大现有侧栏与来源栏宽度。
- **状态色风险**：状态色只替换表现，不修改状态枚举和文案。
- **弹层裁剪风险**：保留现有定位结构，重点用 E2E 验证菜单展开。
- **现有测试风险**：不修改可访问名称和按钮文案，避免无意义测试重写。
- **规范漂移风险**：实现中不自行添加新颜色、阴影、圆角或字体；确需调整时先同步 `DESIGN.md`。

## 6. 完成标准

以下条件同时满足才算完成：

1. `desktop/` 所有现有页面和弹层使用同一套「标本工作台」设计语言。
2. 功能行为、可访问名称和数据流程未改变。
3. 构建、Lint、65 个现有单元测试和布局 E2E 全部通过。
4. 对比度校验全部通过。
5. 三个目标尺寸完成截图检查，未发现溢出、遮挡或旧样式残留。
6. 若实现中调整 token，`DESIGN.md` 已同步更新。
