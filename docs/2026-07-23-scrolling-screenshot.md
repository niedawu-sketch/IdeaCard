# 滚动截图规格与实现计划

> 2026-07-27 状态：实机稳定性未达到可用标准，产品入口已暂时屏蔽。本文件保留为历史规格与后续修复依据，不代表当前可用能力。

## 目标

在现有 `Control + 1` 区域截图流程中增加纵向滚动截图。用户在网页、文档或其他可滚动 Mac 应用中框定固定区域后，通过独立按钮选择普通截图或滚动截图；IdeaCard 主窗口始终保持后台。

## 已确认交互

1. 用户按 `Control + 1`，框选并调整截图区域。
2. 初始工具条显示 `xmark` 取消、`rectangle.stack` 滚动截图与 `checkmark` 普通保存。
3. 未点击滚动截图按钮时，`checkmark` 直接保存普通区域截图。
4. 点击滚动截图按钮后锁定选区并启动连续帧采集；选区外遮罩保持不变，采集就绪后覆盖层对鼠标和滚轮穿透，下方应用按原方式接收滚动。
5. 进入滚动模式后工具条只保留 `xmark` 取消与 `checkmark` 保存，不显示采集段数或常驻进度。
6. `checkmark` / `Enter` 停止采集并进入离线拼接和校验；处理期间不立即关闭截图会话，也不创建卡片。
7. 只有完整长图通过连续性校验后，才生成 PNG、对完整长图执行分段 OCR，并创建标题为 `滚动截图 YYYY-MM-DD HH:mm:ss` 的个人记录卡片；同名时沿用数字后缀规则。
8. 任一帧段无法可靠拼接时整次截图失败，不保存首帧或部分结果，不执行 OCR，不创建卡片。

## 第一阶段边界

- 支持任意 Mac 应用中可见内容的纵向向下滚动，不依赖网页 DOM。
- 反向滚动不回退或删除已经采集的内容；横向滚动与自动滚动不进入第一阶段。
- 最大成图高度为 30,000px，最长会话 2 分钟；达到限制后停止追加并允许保存已有结果。
- 视频、大面积动画、持续变化的画布或无可识别重叠区域可能无法拼接。出现这种情况时明确失败并提示重新截图，禁止保留已有片段作为成功结果。
- 不新增数据库 schema，不新增辅助功能或输入监控权限；继续使用已有屏幕录制权限。

## 原生架构

- AppKit 选择层继续负责框选、调整点、取消与保存。
- 首次滚动后，把全屏选择窗口切换为鼠标穿透；取消/保存迁移到独立的小型控制面板，保持键盘快捷键可用。
- 使用 ScreenCaptureKit 按固定 `sourceRect` 获取帧，并通过 `SCContentFilter` 排除原生 sidecar 自身窗口，避免遮罩、边框和工具条进入结果。
- 滚动模式只由工具条按钮显式启动，滚轮事件不再承担模式切换。
- 进入滚动模式后使用 `SCStream` 以 30fps 连续监测完整帧；在线阶段只做低分辨率连续位移跟踪。帧分析必须在独立串行工作队列运行，界面线程只处理取消与保存，不能因计算积压而合并掉关键中间画面或让按钮失去响应。
- 在线分析使用有界队列：优先保留最早的连续帧，并始终保留最新端点；点击保存后停止接收新帧，等待队列内已接收帧处理完成再进入最终校验。
- 连续帧用于覆盖滚动中的中间位置，但不逐帧参与最终拼接。仅当画面相对上一个锚点向下推进约视口高度的 34% 且存在充足重叠时，才保留为稀疏锚点；在线判断只决定候选帧，不代表长图已经通过校验。
- 保存时停止采集，把最终画面补为末端锚点，再离线以最高 1,024px 宽的细节重新校验全部锚点连接并生成 PNG；在线阶段的快速估计结果不能直接作为成功成图。
- 只处理 ScreenCaptureKit 标记为完整的帧；不完整帧、尺寸变化帧和持续重排的动态内容直接排除。

## 拼接规则

- 只接受存在可信纵向重叠、内容单调向下推进且横向位移不超过 1px 的帧。
- 匹配以文字边缘和其他高信息像素为依据，纯白或近似纯色背景不参与平均，左右各 2% 的边缘区域不参与位移评分，避免滚动条位置变化污染正文判断。
- 把重叠区域分成五个横向信息带独立估计位移；至少三个信息带有效，且最佳候选必须明显优于次优候选。综合评分最多只丢弃一个异常带，不能再用三个重复正文区域覆盖唯一标题、编号或段落的错位证据。
- 固定页头保留在首帧，不参与后续新增区域。跨帧保持零位移的固定底栏或横向滚动条先在全部锚点间求稳定高度，正文拼接时排除，最终只在长图末尾保留一次；检测结果不一致时整次失败。
- 最终拼接只使用稀疏锚点，减少滚动动画中细碎位移的累计取整误差；每个锚点仍必须与前一个锚点单调向下且可靠重叠。
- 完全重复帧直接丢弃；缺少可靠重叠、发生反向滚动、页面持续重排或匹配存在歧义时，整次截图失败。
- 合成只做整数像素裁切：首帧完整保留，后续帧仅追加经过确认的新增底部区域；不缩放、不拉伸、不混合文字像素。
- 保存前对所有接缝做最高 1,024px 宽的灰度细节复核，并验证输出高度、帧连接方向、横向漂移和覆盖连续性；写出后再按原始尺寸重新解码 PNG。任一项不通过就删除临时输出并失败。
- 全过程临时候选帧只能进入会话缓存，不得写入附件目录；成功或取消后统一清理。
- 超过 1,600px 高度的成图按纵向重叠切片执行 OCR，再按阅读顺序合并，避免整张长图缩放识别导致小字精度下降。

## 协议与落盘

- 原生响应在现有路径之外增加 `captureKind`：`region` 或 `scrolling`。
- Rust 仍负责编排 OCR、附件复制、唯一标题和卡片写入。
- 普通截图沿用 `截图 …` / `区域截图`；滚动截图使用 `滚动截图 …` / `滚动截图`。
- 原生必须先完成拼接、校验和 PNG 解码复核，再向 Rust 返回 `scrolling` 成功结果。
- Rust 只对已经通过原生校验的完整长图执行 OCR；取消、原生失败、拼接失败或数据库失败都必须清理缓存文件，不创建残缺卡片。OCR 单独失败时保留已经验证的原图卡片，并记录提取失败状态，禁止用局部 OCR 文本替代完整图片。

## 验证

- 原生单元测试：真实黑字白底内容、唯一标记加重复正文、正常重叠、固定页头、固定底栏、大片空白、快速滚动中间帧、横向漂移、无重叠、反向滚动、页面重排、接缝校验、最大高度、取消清理、普通截图兼容。
- 建立确定性长页面夹具：使用已知总高度和行坐标生成视口帧，拼接结果必须与期望长图逐像素一致；不能只用随机噪声图证明文字页面可用。
- Chrome 实际渲染夹具：固定页头、固定横向滚动条、重复正文和 32 个唯一标记组成 900×3617 长页。所有锚点必须得到真实位移，成图 OCR 必须按顺序识别 `MARK-01` 至 `MARK-32` 且无重复、无缺失。
- Rust 测试：协议类型解析、滚动标题与来源、错误映射、同名后缀。
- 真实桌面测试：Chrome/Safari/Codex 长文本、预览或系统设置等原生滚动视图、固定页头页面、重复列表、触控板连续滚动、鼠标滚轮分段滚动、快速滚动、底部边界、取消和保存。
- 失败保护验收：任何不能确认连续性的案例必须提示失败，附件目录、OCR 记录和卡片表中均不得出现首帧或部分长图。
- 快速滚动验收：在线跟踪不得因细节复核阻塞到丢失相邻位置；同一组连续帧即使离线处理耗时更长，也必须稳定生成与期望页面逐像素一致的长图。

## 2026-07-27 滚动整流（稳定速度上限）更新

人因问题：用户无法知道多快才不会破坏帧间重叠，快速滚轮、回滚、点击页面都会导致帧序列校验失败。改为「用户滚、系统限速」：用户的滚动只表达意图，低速输入保持原速度，超过稳定上限后页面不再加速。

- 滚动截图模式下，全屏遮罩不再穿透：吞掉用户点击（避免误触页面链接）和滚轮事件；滚轮意图按 `isDirectionInvertedFromDevice` 归一化为「向下点数」，忽略向上滚动。
- `ScrollSpeedNormalizer` 以 30 tick/s、每 tick 最多 15pt（约 450pt/s）的稳定上限把意图重放为离散像素滚轮事件（无动量、无橡皮筋），经 `CGEventPostToPid` 直达选区下方窗口所属进程，不经过光标命中。低于上限的输入原量通过；单次或同 tick 累计输入达到上限后，至少连续输出 8 tick 固定 15pt，后续高速输入只把定速窗口续回 8 tick，不增加单 tick 位移。这样可以覆盖真实鼠标滚轮约百毫秒级的突发间隔，又把停手后的最长续滚限制在约 267ms。
- 目标进程优先由 `WindowTargetLocator` 在选区中心按窗口列表自前向后定位（layer 0、排除自身），定位不到时回退到截图层激活前记录的前台应用 PID；两种方式都失败时滚动截图在开始前明确失败，禁止退回原始滚轮直通。
- 自动结束：`BottomDetection` 连续 2s 画面无变化判定到底，自动停止并保存（需至少滚过一帧，否则提示按 Esc 取消）；达到 30,000px 上限同样自动保存。用户仍可随时点 `checkmark` 提前保存。
- 新增权限边界：重放事件需要「辅助功能」权限。助手进程只检查、不弹窗；未授权时滚动截图直接退出并上报 `accessibility_not_trusted`，由**主程序**调 `AXIsProcessTrustedWithOptions` 弹系统授权框（以 IdeaCard 名义登记进辅助功能列表，助手作为子进程继承信任），并发系统通知指引用户勾选后重新截图。
- 防卡死：遮罩、控制面板、提示面板保持最高 screenSaver 层级，截图期间要操作其他应用必须先取消（Esc/✕）；任何失焦（系统弹窗、手动模式下点穿到其他应用、Cmd-Tab）都自动取消并销毁遮罩；助手进程每秒检查父进程，主程序退出即自动取消；Rust 侧 `ScreenshotSessionGuard` 保证不会并发叠加多个截图会话。
- 原生测试覆盖 `ScrollPacing` 的低速原量通过、突发高速触发 8 tick 连续定速、稀疏高速滚轮事件之间不出现零速间隙、持续高速一秒仍不超过 450pt/s、忽略反向与空闲停发，以及 `BottomDetection` 的持续重复判到底和变化后重新计时。
